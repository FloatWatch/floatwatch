탐지 결과와 성능 지표를 / 이후 대응에 활용할 수 있는 기록으로 관리하는 시스템입니다. /

지금부터 / 해양쓰레기 관측 과정에서 어떤 문제를 발견했고, /
이를 서비스 기능과 AI 모델 학습으로 어떻게 해결했는지 말씀드리겠습니다. /

프로젝트 일정입니다. /

모델별 바운딩 박스와 성능을 비교하고, / 분석 기록을 다시 조회할 수 있도록 상세 화면도 개선했습니다. /

4주차에는 / 네 종류 AI 모델을 추가 학습하고 동일 검증셋을 기준으로 성능을 비교했습니다. /
또한 브라우저 카메라 기반 실시간 탐지와 / 위치 지도, 탐지 증거 기록 기능까지 구현했습니다. /

현재 1주차부터 4주차까지의 목표는 완료했으며, /
5주차에는 전체 기능과 예외 상황을 통합 테스트하고 / 최종 모델과 발표 시나리오를 정리할 계획입니다. /


(슬라이드 5 · 프로젝트 개요)

다음은 프로젝트 개요입니다. /

해양 부유물은 / 해양 생태계와 연안 환경을 지속적으로 위협하고, /
선박 운항과 안전에도 영향을 줄 수 있습니다. /

하지만 넓은 해역을 사람이 반복해서 관찰하는 방식은 / 많은 시간과 인력이 필요하고, /
부유물을 놓치거나 대응이 늦어질 가능성이 있습니다. /
영상 판독과 결과 관리까지 수작업으로 진행하면 / 기록이 분산되어 이후 분석에도 활용하기 어렵습니다. /

저희는 이 문제를 / 환경, 사회, 기술의 세 관점으로 정리했습니다. /
AI로 영상 속 부유물을 빠르게 탐지하고, / 위치·종류·성능 지표를 하나의 기록으로 연결해 /
담당자의 판단과 대응을 지원하는 것이 프로젝트의 목표입니다. /


(슬라이드 6 · 수요 조사)

다음은 수요 조사입니다. /

해양수산부 자료에 따르면 / 연간 해양쓰레기 발생량은 약 14만 5천 톤이며, /
경제 피해는 약 4천억 원, / 선박 추진기 감김 사고는 연평균 378건으로 제시되고 있습니다. /

2024년에는 수거와 처리, 발생 예방 등에 / 약 1,547억 원의 국비가 투입됐습니다. /
또한 인천광역시는 / AI와 드론을 활용한 해양환경관리 사업에 약 70억 원을 투자해 /
탐지와 수거 경로 최적화를 추진했습니다. /

이 수치들은 해양쓰레기 문제가 일시적인 현상이 아니라, /
지속적인 관측과 관리, 효율적인 대응 체계가 필요한 문제임을 보여줍니다. /
따라서 부유물의 위치와 종류를 빠르게 확인하고 / 결과를 누적해 활용할 수 있는 분석 시스템이 필요하다고 판단했습니다. /


(슬라이드 7 · 기술 스택 및 시스템 아키텍처)

다음은 시스템 아키텍처입니다. /

프론트엔드는 Next.js와 TypeScript로 구성해 / 서비스 화면과 모델별 결과를 시각화했습니다. /
백엔드는 FastAPI와 SQLAlchemy를 사용해 / 사용자 인증, 모델과 미디어 검증, 네 개 모델의 분석 묶음을 처리합니다. /

AI 추론 영역에서는 Ultralytics와 OpenCV를 활용해 /
등록된 대표 모델로 이미지와 영상 프레임을 분석하고 바운딩 박스를 생성합니다. /
파일 스토리지에는 모델, 원본 미디어, 결과 파일을 저장하고, /
SQLite에는 계정, 대표 PT, 분석 묶음과 성능 지표를 저장합니다. /

전체 분석 흐름은 / 대표 PT와 미디어 준비, 유효성 검증, 등록 모델 순차 추론, /
모델별 결과와 지표 기록의 네 단계로 동작합니다. /


(슬라이드 8 · 기능 소개)

주요 기능은 / 업로드 기반 분석과 실시간 탐지, 두 가지 흐름으로 구성했습니다. /

먼저 업로드 기반 분석입니다. /
사용자는 네 모델 계열마다 분석에 사용할 대표 PT를 지정하고 / 이미지나 동영상을 등록합니다. /
분석을 시작하면 동일한 미디어를 등록된 대표 모델들이 일괄 분석하며, /
일부 모델이 등록되지 않은 경우에는 해당 모델만 제외하고 분석을 계속합니다. /

분석이 끝나면 모델 탭에서 바운딩 박스를 확인하고, /
클래스별 탐지 수와 평균 신뢰도, 전체 탐지 수와 처리 속도를 비교할 수 있습니다. /
결과는 하나의 분석 묶음으로 저장되며 / 탐색 기록에서 다시 조회할 수 있습니다. /

두 번째는 실시간 탐지입니다. /
현재는 브라우저 카메라를 테스트 카메라로 연결하고, / 관측 지점과 위치 정보를 함께 등록하도록 구현했습니다. /
적용할 모델을 선택하면 / 카메라 프레임에서 클래스, 신뢰도, 바운딩 박스를 실시간으로 확인할 수 있습니다. /
탐지 시간과 위치, 클래스, 증거 이미지는 세션 단위로 저장되어 / 이후 기록 화면에서 다시 확인할 수 있습니다. /

이외에도 공지사항, 자유게시판, FAQ, 1대1 문의와 안내 챗봇, /
회원 권한과 분석 로그, 문의 답변, 관리자 감사 로그 기능을 구현했습니다. /


(슬라이드 9 · AI 리포트 A — YOLOv8s·YOLO11s 학습 개선 과정)

다음은 YOLOv8s와 YOLO11s의 학습 개선 과정입니다. /

각 차수는 이전 가중치를 이어받은 전이 학습이 아니라, /
앞선 결과에서 확인한 문제를 데이터 구성과 학습 조건에 반영해 / 매번 독립적으로 다시 학습한 실험입니다. /

1차 학습에서는 / 11개 클래스, 총 18,710개의 불균형한 기본 데이터로 기준 성능을 확인했습니다. /
클래스별 객체 수가 196개에서 7,064개까지 차이가 나 / 취약 클래스의 성능 편차가 나타났습니다. /

2차 학습에서는 / 두 모델의 데이터 분할과 입력 크기, 옵티마이저를 통일해 /
모델 구조에 따른 차이를 비교했습니다. /
그러나 두 모델의 Recall이 약 80% 수준에 머물러 / 데이터 균형을 다시 조정할 필요가 있었습니다. /

3차 학습에서는 / 전체 객체를 23,125개로 확대하고, /
클래스당 1,306개에서 2,725개 수준으로 균형화했습니다. /
입력 크기 800픽셀, Batch 8, 100 Epoch, AdamW와 학습률 0.001을 적용하고, /
Scale을 0.2로 낮춰 과도한 변형을 줄였습니다. /

그 결과 YOLOv8s와 YOLO11s의 Precision은 각각 92.08%와 92.74%, /
Recall은 89.64%와 88.46%, / mAP50은 94.36%와 93.83%, /
mAP50–95는 81.52%와 82.06%를 기록했습니다. /

[필요 시 그래프·예측 사진·혼동 행렬 탭을 차례로 선택]
각 탭에서는 학습 그래프와 실제 예측 결과, / 클래스별 정답 예측과 오분류 패턴을 확인할 수 있습니다. /

다음 학습에서는 / 혼동행렬에서 확인한 취약 클래스의 미탐지 표본과 라벨을 다시 점검하고, /
과도한 증강을 줄인 뒤 다중 Seed 반복 학습으로 / Recall 90% 이상과 결과 재현성을 검증할 계획입니다. /


(슬라이드 10 · AI 리포트 B — YOLO26s·RT-DETR-L 학습 개선 과정)

다음은 YOLO26s와 RT-DETR-L의 학습 개선 과정입니다. /

1차 학습에서는 / 6배 증강 데이터셋과 동일한 학습·검증 분할을 적용해 /
YOLO 계열과 Transformer 계열의 기준 성능을 비교했습니다. /
이때 Recall은 YOLO26s 79.82%, RT-DETR-L 81.37%로 / 두 모델 모두 추가 개선이 필요했습니다. /

2차 학습에서는 / 11개 클래스, 총 23,125개의 균형화 데이터셋을 사용했습니다. /
두 모델 모두 입력 크기 800픽셀, Batch 4, 100 Epoch, /
AdamW와 학습률 0.001, 동일한 증강 조건을 적용했습니다. /

YOLO26s는 Precision 92.79%, Recall 87.88%, /
mAP50 93.67%, mAP50–95 81.35%를 기록했습니다. /
새로 반영한 RT-DETR-L 2차 결과는 / Precision 91.50%, Recall 88.63%, /
mAP50 92.95%, mAP50–95 75.28%입니다. /

즉 YOLO26s는 Precision과 mAP 지표에서 상대적으로 우세했고, /
RT-DETR-L은 Recall에서 0.75%포인트 높아 / 놓치는 객체를 줄이는 측면에서 강점을 보였습니다. /

[필요 시 그래프·예측 사진·혼동 행렬 탭을 차례로 선택]
두 모델 모두 그래프, 예측 사진과 정규화 혼동행렬을 같은 방식으로 확대해 확인할 수 있습니다. /

3차 학습에서는 / Rope와 Styrofoam Piece처럼 남아 있는 취약 구간을 집중 보강하고, /
배경으로 누락된 객체와 유사 배경의 오탐 사례를 추가할 계획입니다. /
동일 조건의 다중 Seed 학습으로 / Recall 90% 이상과 성능 재현성을 함께 검증하겠습니다. /


(슬라이드 11 · AI 리포트 C — 최종 PT 기준 3D 비교)

다음은 네 모델의 현재 최종 PT를 기준으로 구성한 / 인터랙티브 3D 혼동행렬 비교입니다. /

YOLOv8s와 YOLO11s는 3차 학습 최종 PT, /
YOLO26s와 RT-DETR-L은 2차 학습 최종 PT의 정규화 혼동행렬을 사용했습니다. /

X축은 실제 정답 클래스, / Y축은 모델이 예측한 클래스, /
Z축은 실제 클래스별 정규화 예측 비율입니다. /
점의 색상은 각각의 모델을 구분합니다. /

[그래프를 천천히 드래그해 대각선 방향이 보이도록 회전]
실제 클래스와 예측 클래스가 같은 대각선 위의 점은 정답 예측을 의미하고, /
대각선에서 벗어난 점은 다른 클래스로 잘못 예측한 결과를 의미합니다. /
그래프가 지나치게 복잡해지지 않도록 / 정답 예측은 모두 표시하고, /
서로 다른 클래스의 오분류는 10% 이상인 경우만 표시했습니다. /

[한 점에 마우스를 올리거나 선택]
각 점을 선택하면 / 모델 이름, 실제 클래스, 예측 클래스와 해당 비율을 확인할 수 있습니다. /
마우스 휠과 우측 확대 도구로 원하는 영역을 자세히 볼 수 있고, /
시점 초기화 버튼으로 처음 화면으로 돌아갈 수 있습니다. /

최종 PT의 클래스별 대각선 평균은 / RT-DETR-L 91.27%, YOLO26s 86.27%, /
YOLOv8s 84.45%, YOLO11s 81.73% 순으로 나타났습니다. /
다만 이 값은 혼동행렬의 클래스별 정답 예측 비율을 평균한 값이므로, /
전체 모델 선정에서는 Precision, Recall, mAP와 추론 속도까지 함께 고려해야 합니다. /


(슬라이드 12 · 서비스 직접 시연)

이제 별도의 녹화 영상 대신 / 실제 구현된 서비스 화면에서 핵심 기능을 직접 보여드리겠습니다. /

시연은 / 미디어 업로드, 네 개 모델 일괄 분석, 결과 비교, 실시간 탐지 순으로 진행하겠습니다. /

[실제 서비스 화면으로 전환]

먼저 분석할 이미지 또는 영상을 등록하겠습니다. /
이후 동일한 미디어를 네 개 대표 모델로 분석하고, /
